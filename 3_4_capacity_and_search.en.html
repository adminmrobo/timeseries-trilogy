Complex, and Efficient — Capacity and Optimization

How do we build a space wide enough to contain the answer, and within it how do we find the answer quickly?

Neural network training boils down to two points. Keep the space wide (grow capacity with layers and neurons), and search efficiently (descend along the slope of the loss function). Both also need an answer key to run. We check these two points by changing the number of hidden neurons and the learning rate ourselves.

Dialogue notes — “One element as complex as possible, the other as efficient as possible”

Original dialogue, verbatimLedger: find the settings that produce the smallest loss

🙋 Asker
Neural network models seem to approach things differently. With the answer key already in hand, one element is made as complex as possible (layers, dense), and the other is made as efficient as possible (cost function) to find the optimum.
💬 Answerer

That’s a very neat summary of neural network training.

Complex ─────┐ (space to express) ├──→ balance → optimum Efficient ───┘ (way of searching)

① As complex as possible — capacity

Input → LSTM(128) → Dense(64) → Dense(32) → Output

Make the layers deep and the connections dense to build a space wide enough to contain the answer.

② As efficient as possible — optimization

loss = MSE(answer, prediction) optimizer = Adam(lr=0.001) Repeat: predict → compare with the answer → adjust along the gradient

In that wide space, it descends along the gradient of the cost function by the shortest path.

③ And the “answer key”

ApproachStarting pointDirection
Traditional mathematical modelTheory and assumptionsTheory → model → verify with data (deduction)
Neural networkData with answers attachedDiscover from data → structure → search (induction)

📝 Addendum: “It descends by the shortest path” is a bit of an exaggeration. The slope is only the steepest direction from where you stand right now, so if the terrain is curved, you may zigzag. See it for yourself in the ball-rolling experiment below. And a third axis is hidden in this balance, which we cover in 3-5.

1Complex

Adding hidden neurons increases the curves that can be drawn

Model: ŷ = Σ wⱼ·tanh(aⱼx + bⱼ)Ledger: add cost-item cells

In ledger terms

If the ledger has only one column, “sales,” it cannot record every twist in profit and loss. The more columns (items) you add, the more complex flows you can record. But as columns multiply, so does the effort of filling them in.

In the model

One hidden neuron is one piece of a tanh curve, that is, one new axis. Adding pieces makes a curve, and the more pieces there are, the wider the range of curves you can draw (capacity). Change the number of hidden neurons and try to fit the same wavy curve.

See it in action — the piece each hidden neuron draws

Walkthrough — building a curve by adding pieces

  1. 1 neuron: one tanh piece, so it can draw only one S-shape. It cannot follow the waves.
  2. As you add neurons, the pieces increase, and their sum follows the waves. The faint lines in the figure below are each piece.
  3. This experiment trains on the same 80 points and measures error on the same points (training error). Whether it fits well on unseen points is a different question.

Limit of this step · Widening the space only raises the chance that the answer is inside. Finding that answer (②), and generalizing without memorizing (overfitting in 3-5), remain separate problems.

The math — a neural network with one hidden layer
ŷ(x) = c + Σj=1..H wj · tanh(ajx + bj)

It is a well-known property that even with one hidden layer, if the number of neurons H is increased enough, you can approximate a smooth one-dimensional curve as closely as you like. In practice, stacking layers instead of increasing H often yields more complex shapes for the same effort. Target curve: sin(4x) + 0.6·sin(11x) + small noise; training: Adam, 500 iterations, seed 11.

2Efficient

Rolling a ball over the loss landscape — learning rate and update methods

Model: w ← w − η·∇L(w)Ledger: toward the direction where the loss shrinks

In ledger terms

Each time you change the two settings (w₁, w₂), the loss on the ledger changes. You cannot try every combination, so you move a little at a time in the direction where the loss falls fastest from where you are. If you move too far at once, you bounce off to the opposite wall.

In the model

The gradient ∇L of the loss function L(w) is computed by backpropagation[1]. Gradient descent walks opposite the gradient by the learning rate η. Momentum keeps going in the direction it was already moving, and Adam adjusts the step size for each parameter.

Update method

Walkthrough — how the ball rolls

  1. The terrain is a bowl stretched in one direction. The slope in the steep direction (short axis) and the gentle direction (long axis) differs by 20 times.
  2. With GD, if η is raised above 0.1, it bounces off the opposite wall in the steep direction with growing swings and flies out (divergence). If it is too small, it crawls very slowly along the gentle direction.
  3. Momentum reduces zigzagging but can overshoot and swing back. Adam tends to go straight by evening out the step sizes in both directions.
  4. The landscape of a real neural network has millions of dimensions and is not as smooth as a bowl. This figure only shows “why the learning rate and update method matter.”

Limit of this step · A gradient only carries information about the current spot. If the widely built space (①) is bumpy, even an efficient update method can stall in a nearby valley.

The math — three update methods
GD: w ← w − ηg | Momentum: v ← 0.9v + g, w ← w − ηv | Adam: m ← 0.9m + 0.1g, s ← 0.999s + 0.001g², w ← w − η·m̂/(√ŝ + ε)

Terrain: L(w) = ½(w − w*)ᵀH(w − w*), H with eigenvalues 1 and 20 (rotated 30°). GD converges in the steep direction only when η < 2/20 = 0.1. Even with the same η, the actual step size differs by update method, so the numbers cannot be compared directly.

3Answer key

Induction starting from the answer key, deduction starting from theory

Model: data → structure → searchLedger: past ledgers are the answer key

ApproachStarting pointDirectionIn this series
Traditional mathematical modelTheory and assumptionsTheory → model → verify with data (deduction)ARIMA: assume stationarity, differencing, and order, then fit
Neural networkData with answers attachedDiscover from data → structure → search (induction)LSTM: looks at (window, next day) pairs and finds the weights
In ledger terms

Each day of a past ledger already carries its “next-day answer.” A 200-day ledger therefore has 193 to 186 answer sheets (depending on lookback). The neural network reads these answer sheets and reduces the loss.

In the model

Without an answer key, ① and ② do not run, because the loss function cannot be computed. By contrast, ARIMA fills the gaps with the assumptions of “linearity and stationarity,” even when there are few answers. The two directions are not opposites; they differ in their starting points.

Walkthrough — practice that mixes deduction and induction

  1. ARIMA also estimates its coefficients from data. It is not pure deduction; it leans toward “heavy assumptions.”
  2. For LSTM too, people set the structure (number of layers, lookback, loss). It is not pure induction; it leans toward “handing a large share to the data.”
  3. The hybrid model (ES-RNN) in 3-3 is an example of mixing both directions within one model.

Limit of this step · “Learning from the answer key” is weak in situations not covered by the answer key (a new event, a season never seen before). This leads to the overfitting and generalization problems on the next page.

The math — where the answer key enters
θ* = argminθ (1/N) Σn ℓ( yn, fθ(xn) ) — yn is the answer key

Neural network training is this one equation. ① is the shape of fθ (capacity), ② is the method for finding the argmin (optimization), and ③ is yn (the answer key).

Professor

This method only runs with an answer key. It starts from a different point than the path down from theory, but both are validated with data.
